The Retail input snapshot recorded a visible, mouse-enabled `FluxUnitFrameOuter_player`, its native `SecureUnitButton_OnClick` handler, `unit=player`, `*type1=target`, and mouse focus directly on that button. The user restored **Target Unit → Left Button** through Blizzard's Click Casting UI and confirmed that left-click then worked. Flux does not reset or replace the native click-casting profile. This is a confirmed Retail observation, not a five-client native test.

Version 2 saves partial evidence before native reads, tolerates restricted parent/script reads, records completion and shows a timestamped capture acknowledgment. Reload flushes that snapshot through normal SavedVariables. It installs no native hooks, input changes, permanent frame or polling loop. [Its test](../tests/input_diagnostics.lua) checks false values, secrets, restricted reads and bounded scheduling.

### Stance flicker, player artwork containers and retained idle optimization

The user subsequently identified form-change flicker on **Retail**, reported idle FPS near 200 versus near 300 on **Forever**, and clarified that the FPS regression also affects **Retail and the other clients**. These are user observations; the current saved performance sample is Forever only. The source investigation therefore covers shared paths across all five clients. The prior secure stance callback hid only the parent. Blizzard's `StanceBarMixin.Update` updates buttons and then calls `SetShown` on the parent; a child left shown can therefore reappear. Hiding that parent inside a child callback can also reenter its native `OnShow`/`Update` when the native update tail shows it again.

The stance callback now hides the replaced button through its restricted frame handle. The restricted setup/callback also suppresses the parent's alpha and mouse input through Blizzard's captured widget methods, without replacing its mixins or invoking its Lua `HideOverride`. The parent may retain native shown state, while its artwork and input stay suppressed. Initial setup remains out of combat and gated on Flux input readiness; callbacks installed legally beforehand can run in combat. Classic hidden parenting, Forever's paging capability gate, original native button callbacks and actual possess/cancel controls remain intact. No visibility polling or timer is added. This is secure-handler code, not insecure `SetAlpha`/`EnableMouse` calls on the controller.

The [stance smoke](../Core/_tmp_stancehidesmoke.lua) now executes the supplied native `HANDLE:Hide`, `HANDLE:SetAlpha` and `HANDLE:EnableMouse` methods. Alongside 800 combat show callbacks, it runs the actual Retail and Forever `StanceBarMixin.OnShow`, `Update` and `ActionBarMixin.UpdateShownButtons` methods with mocked button APIs across repeated form updates. It asserts bounded parent entry, suppressed button/root input and preserved callbacks. [Bar contracts](../tests/bars_contract_regression.lua) retain their existing assertions and add a negative control that removes child suppression. These checks do not execute WoW's secure VM; clean Retail/Forever form and combat checks remain required.

The unused native `PlayerFrameContainer` is now hidden alongside `PlayerFrameContent`, with per-container original visibility snapshots and exact restoration when returning to native frames. These named decorative containers have no show/hide scripts in the supplied modern XML. The player root, vehicle/aura handling and independent resource, pet, totem and cast controls remain intact. Missing legacy containers are ignored. No new native script hook or idle driver is installed. [Mouse tests](../tests/native_mouse_suppression.lua) cover both containers, originally hidden state, native re-show, repeated reconciliation, combat/Edit Mode barriers and twelve negative controls. The diagnostic records both nested containers and distinguishes native action bars' logical `IsShown` from physical `IsShownBase`.
