# FluxUI inventory performance roadmap

**Acceptance baseline set on 20 November 2026.** The optimization pass closed with 82 passing regression scripts and 90 compiled, matching Lua sources across five installed client families. All 90 source hashes still match the closeout. The next milestone is one live acceptance pass of the current FluxUI build.

The roadmap tracks both inventory-triggered frame spikes and passive CPU work. Preserve appearance, features, update timing, controls, settings and item counts. Scope includes the FluxUI inventory bridge and both Extra Button grids across Retail, Forever, Classic progression, Classic Era and Anniversary. Syndicator and Baganator source stay under their respective owners. Polestar, border changes, guild bank and void storage are outside this roadmap.

## Finish point

Record the outcome, client build, source identity, provider configuration and evidence for each row. Use **Pass**, **Regression**, or **Unavailable** for each live action. Check first-run behavior and a short repeat where applicable. Fix only reproducible FluxUI failures in the six checks, then rerun the affected checks. For a performance-only change, use at least three matched samples for each version and check that the improvement is larger than run-to-run variation. A callback time reduction supports a frame-time claim only when matched frame measurements show it too.

**Stop after this pass and its focused retests.** Close the goal once the required cases pass. Record the specific setup for any unavailable required case and revisit it when the setup changes. Accepting deferred required coverage needs the user's agreement. Keep new optimization ideas and the proposed crafting cache in the backlog.
