# Transmog flyouts and draggable clear action — 23 October 2026

The shared character-button/player-portrait outfit flyout now puts **Clear Current Transmogrifications first**, followed by the existing outfits in player-facing index order. Clear is available even without saved outfits when the character exposes the native clear API. Character-button entry points include the micromenu and chat column. Existing outfit activation and active-state borders remain supported.

Both clear and saved outfits can be dragged from those flyouts, dropped onto Extra Button System buttons, moved between buttons and dragged back off. Utility slots and their options editor also accept native outfit cursors. Assignment persistence and utility snapshots retain `outfit` identity `0` for clear. Sparse saved outfit IDs are resolved to the current player-facing index when configuring secure input; identity and index are not interchangeable.

The first implementation missed existing clear buttons stored as `spell` actions. The affected Forever SavedVariables contained spell ID `1247917`, matching that branch's `CLEAR_TRANSMOG_OUTFIT_MANUAL_SPELL_ID`; normal outfits were already stored as outfit actions. Ordinary spell pickup cannot be assumed for that synthetic spell face: Blizzard's clear control explicitly uses `PickupOutfit(0)`. EBS and utility drag-off now recognize the native clear spell constant and use that pickup path, retaining existing saved assignments until the player successfully moves/removes them. New spell-form clear cursors normalize to outfit ID zero. No player SavedVariables are edited by a migration, and ordinary spell/flyout pickups keep their original identity and precedence.

The user subsequently reported that the clear icon followed the cursor while the source stayed assigned. The pickup-success check still accepted only an `outfit` cursor. It now also recognizes the clear spell cursor produced by a successful clear pickup, checking the real spell ID (fourth return where provided) against the native clear constant. An unrelated spell, spellbook slot number or different outfit cannot authorize removal. This is a cursor-contract correction; it adds no timers or protected actions.

The implementation uses Blizzard's native `PickupOutfit(0)` cursor contract and secure `/outfit` activation. It never calls ClearOutfit or ChangeToOutfit directly from a drag callback. Failed pickups retain the existing assignment. Unknown or unsupported outfit drops leave both the cursor and destination intact. Combat refuses structural drag changes; outfit-list refreshes coalesce through the existing combat queue and reconcile after combat. A saved outfit whose journal data is temporarily unavailable retains its identity with inactive input until data arrives.

Utility slots with outfit variants configure each exact modifier chord separately. This prevents a clear action from falling through when another modifier selects a spell, item, outfit or user macro. Unassigned chords keep the existing base/mirror selection. Icons, tooltips, the shared outfit cooldown and active-state display use the common engine; outfit change events drive refreshes without adding an idle ticker.

## Verification

[transmog_actions.lua](../tests/transmog_actions.lua) executes production API, flyout definition/drag handler, complete EBS action engine, utility assignment/snapshot code, modifier attribute generation and complete utility interaction wiring. It covers all five branch models, simulated capability availability on older branches, clear-first ordering, sparse identities, drag-in/off/swap, persistence, failed pickups, unavailable journals, locked buttons, combat refusal, coalesced recovery and mixed modifier actions. Regressions for ordinary clear-spell pickup producing no cursor and successful native pickup yielding a clear spell cursor both failed before their respective fixes. Existing spell-form/outfit-form EBS and utility assignments are covered, and the actual minimap persistence/restore functions prove drag-off clears both saved aliases and cannot restore the removed action on reload. Ordinary flyout spell and stash behavior has executable coverage in addition to the updated source contract. Six targeted negative controls prove the assertions reject regressions.

The [full validation record](validation/transmog-actions-2026-10-23.json) records syntax, smoke results and normalized source hashes. These are desktop mocks, not native protected execution or FPS measurements.

Native verification remains required on Live and Forever: open both character and player flyouts; confirm clear is first; drag clear and a saved outfit onto/between/off category, minimap and utility buttons; reload; activate each assigned action; rename/reorder/delete an outfit; exercise all modifiers with mixed spell/item/macro variants; verify icons/tooltips/cooldowns and combat/taint behavior. On Era, Anniversary and progression Classic, confirm unsupported outfit controls stay absent and existing button types still work. No in-game transmog test was performed during this change.
