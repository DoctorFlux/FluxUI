# P0-to-current follow-up: shared resource lifecycle

The four P0 protections remain in the current checkout: automatic verification preserves customized bindings; failed Respec restoration retains its recovery checkpoint; Baganator uses local item-identity adapters; validated migrations retain legacy configuration. Their seven source files remain identical to `72fb194`. The [history audit](54-history-p0-startup-audit.md) distinguishes those retained fixes from subsequent local changes and the older v9 backup. Reapplying identical P0 code would not change idle FPS.

This follow-up changes two shared unit-frame implementations. It does not restore the earlier native-frame hooks, reparent native Edit Mode systems, replace Blizzard functions, change bindings/settings, alter map providers, or freeze/remove animated portraits.

## Changes

- [Spell-cost watchers](../UnitFrames/FluxPowerCostOverlay.lua) retain one event frame per unit frame across option application, disable/re-enable and unit rebinding. Previous code unregistered and discarded each watcher, then allocated another. WoW cannot destroy those discarded frames. The retained watcher is assigned before event setup so a failed initialization can retry without another allocation. Rebinding still clears old events and rebuilds callbacks for the current unit and bars; a disabled watcher has no events or handler.
- Disabling the feature now also stops its secret feedback animations, invalidates delayed ghost updates and hides its unused ghost/cost meters. Previously, a pending next-frame commit could show the ghost again after disable. Re-enabling primes current resource state instead of retaining stale feedback.
- [Resource sparks](../UnitFrames/FluxUnitFrames_Shared.lua) retain completed anchors, atlas and readable scale. The fill-relative anchor continues to follow live power. Every paint still checks widths, full/empty state and `showAtMax`; style changes, atlas readiness, replacement fills and resizing remain immediate. A failed write is retried. Secret/inaccessible heights are not compared or cached. Atlas support and the existing HUD/classic capability gates remain.

[Production replay](../tests/unit_resource_lifecycle.lua) runs against retained earlier bodies and the current source across five client models. One hundred initialize/disable/re-enable cycles allocate **201 → 1 watcher frames** per unit frame. Three hundred unchanged spark paints perform **1,200 → 4 style writes**. These are synthetic operation counts, not measured FPS improvements. Tests cover ongoing casts at setup, cast/channel payloads, completion/interruption, unit filters/rebinding, disabled callbacks, failed setup/retry, pending ghost commits, animation cancellation and resumed feedback. Spark checks cover capability gates, live visibility, style mutation, replacement fills, missing/late atlases, resize, write failures and secret dimensions. Seven targeted mutations are rejected.

## Native capture and remaining gap

Before these resource changes, the audit recorded a [fresh Forever CPU capture](validation/forever-idle-re-audit-profiled-2026-10-23.json), build 70532, with the Map tab open and World Map/Character panel closed. The external monitor recorded **43/43 half-second focus samples** in `WowB`. Flux measured **4.72 ms/s**, with native recent averages of **0.035 ms/tick for Flux** and **4.487 ms/tick for the application**. Profiling was enabled; its 219 FPS average is not an unprofiled acceptance result. Function/frame rankings are inclusive and must not be added together.

The remaining visible Flux press driver measured 1.99 ms/s; native chat, map and quest-navigation callbacks also remained active. Native rendering cost is not included in addon Lua CPU. The capture does not identify a single cause for the reported FPS gap, and the character being a ghost is recorded only as scene context, not an explanation.

The user prefers to keep Forever in the background while using other applications. The capture procedure restored `scriptProfile=0`, reloaded and stopped foreground input. A short unprofiled sample subsequently lost focus (12/14 monitor samples in WoW), so it was rejected as a foreground comparison. No graphics/background FPS CVars were changed. A foreground FPS comparison, native testing of these new changes and the unresolved first Edit Mode taint writer remain outstanding. The code changes load on the next normal reload; file synchronization alone does not update executing Lua.
