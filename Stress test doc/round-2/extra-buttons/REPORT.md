# Round 2: Extra Buttons, ButtonFX and badge ownership

This audit did not modify addon code, existing tests, TOCs, settings or profiler preferences, and did not control the game. It wrote only this new evidence folder. Current source is authoritative; earlier checkpoint code was not restored. The [round-2 baseline](../baseline.json), [fresh client pins](../upstream-pins.json) and [timer contracts](../timer-contracts.json) belong to the parent audit.

The strongest current findings are a broken mount refresh debounce, repeated mount-journal enumeration, and vendor detection that depends on English display names. The conditional cooldown recovery case and dormant legacy typo have different evidence and priority; neither is a newly observed native taint error.

## Reproductions and limits

[ebs_round2.lua.txt](ebs_round2.lua.txt) loads the complete current Usability, MountCollection and Charges modules, plus exact current config/caller functions. It performs20,032 assertions per run. Its10,000 macro pairs across five labeled client models yield5,000 mismatches plus five conditional inventory-slot mismatches in the dormant helper. An isolated in-memory correction of the two literal searches selects the modeled active clause. No proposed code was written into an addon source file. This is a legacy helper defect, not proof that current utility macro routing is wrong.

The mount models contain1,000 collected entries and retain the same synthetic vendor identity while varying its public provider name. English detection passes; the localized-name and ordinary-mount controls fail detection as predicted by the source. The exact config lookup does2,000/3,000 `GetMountInfoByID` calls per invocation. The complete current `Module.Update` and its actual middle-click/vendor helper reach that lookup once per modeled full update with unrelated rendering/layout services stubbed quiet.100 updates repeat the full enumeration. The existing collection map needs1,000 initial queries and zero more for100 subsequent helper calls. Event frequency, actual collection size, native API cost and full-update wall time were not measured. Mount updates can be driven by collection, readiness, zone and skill changes; modifier-only icon updates were not relabeled as full updates.

[mount_timer.lua.txt](mount_timer.lua.txt) executes the exact timer alias, actual `HasMountUI` gate and current `OnSpellBookChanged` function.40 checks cover five labels in/out of combat. Native `After` returns nil. Era, Anniversary and the existing Forever major-version1 gate each schedule100 extra0.3-second bag callbacks after100 handler invocations; Retail and progression do not enter that branch. Outside combat, the independent0.5-second callbacks produce another100 full-update calls. During continued combat, the100 bag callbacks run without painting. These are injected event bursts, not observed native event rates. The current mainline client source contract is verified for the four requested branches; progression is an additional existing model.

[reticle_disabled.lua.txt](reticle_disabled.lua.txt) reuses the current `utility_modifier_vfx` fixture and its complete Cast module. It also executes the real Overlay `VfxAllowed`/`PlayReticle` early guard while disabled.805 fixture/control assertions pass per run. Three Classic models each retain the targeting ticker and perform36,000 resolver/36,000 alpha reads across600 ticks and60 extra faces. Actual rendering remains off; targeting cancellation disarms the ticker. Modern VFX intentionally remain enabled by current policy. The shared ticker is frame driven; the experiment counts600 callbacks and does not infer FPS or native elapsed time from the supplied elapsed argument.

The Charges test executes the complete current module with legal public timer values. Failure is deliberately injected once at the native setter boundary. This proves an application-success/cache mismatch under failure, not that a normal public cooldown setter currently fails in any client. The unchanged successful-timer control preserves one native write across1,000 paints, and explicit `ClearCache` permits recovery. A fix must retain that success-path budget.

## Coverage and source identity

Current source load order matters: `ExtraButtonSystem/Init.lua` declares the active facade; Widget/Action/Paint/Watch/Range/Style/Badge load from the TOC. Old Engine Button/Core/Events/Usability/Util and old Flyout are dormant. They were inspected as legacy code but not used to claim a current runtime failure. The active config/MountCollection/Mount and Core ButtonFX modules do load. No new direct native taint failure was established in this slice. These tests cannot prove protected-action permissions, native secret-value behavior, pixel parity, frame time, native secure input or taint provenance.

The assigned sweep covered modifier/mixed spell/item/pet faces; journal and bag mounts; consumable best selection and depletion; conjured charges/restock/weapon targets; aura/countdown ownership; cooldown signature/alpha/duration behavior; badge identity/visibility; cast/channel/empower/reticle/burst/interrupt/proc transitions; frame/registry reuse and hidden paint gates. Dungeon/raid metadata was not pretended to exercise an instance-specific branch here. Whole-addon instance coverage belongs to the parent audit.

Their outputs and timings are preserved in [results.json](results.json). All other existing script stdout matches byte-for-byte.
