# Alpha-reader fix proposals — isolated, not applied

Six concrete candidate files are frozen outside AddOns at the `alpha-readers` candidate root recorded in [workspace.json](../workspace.json). [The manifest](candidate-manifest.json) records their exact baseline/candidate byte hashes and six reviewable patches. No live addon source, existing test, game input, profiler preference or settings file was written by this work. The candidates retain the frozen baseline's newline/BOM conventions and existing library attribution/license.

**These are conditional simulation candidates, with explicit application gates.** They address operations on unreadable *return values* in the supplied models. Several still call an alpha getter whose operation itself can be denied. The unknown native frame/provenance behind USER-001 has not been identified by these tests, and these proposals are not a claim that its native taint is fixed.

The threat caller change belongs to the separately owned `geometry` candidate `UnitFrames/FluxUnitFrames_Shared.lua`; this agent did not edit that file. Its requested hunk removes the pre-call `_fluxThreatGlowBand` commit, captures the existing LCG/LBG `pcall` success, and commits only on success. A successful nil API return remains valid. A failure retains the old band so an ordinary later call can retry; it adds no retry timer. The geometry report holds its failure/retry/success tests.

**The Shared retry/cache hunk and a corrected, confirmed winning renderer are a coupled application gate.** If a higher external LCG still owns the old unreadable-alpha operation, committing only after success can cause more repeated failed attempts on ordinary threat paints than the old prematurely committed band. Do not apply the Shared retry hunk alone while renderer ownership is unresolved. The combined prototype's fresh patched embedded minor20 model is valid within its stated scope; an unfixed external winner is not accepted.

## Test evidence

`python 'Stress test doc/fix-proposals/alpha-readers/run_tests.py'` runs the candidate against the frozen external baseline. [Results](results.json) retain all consumed hashes before/after, the exact harness, three raw logs and syntax outcomes.

- **619 assertions pass per repetition**, including seven old-code unreadable-alpha rejections and **240 exact public parity comparisons**: eight routes × six alpha values (0,0.01,0.4,0.40001,0.75,1) × five client-model labels. Classic versus ordinary swipe transparency is included.
- Three repetitions have **1,857 assertions and 21 repeated baseline rejections**. They reuse the same scenarios; repetition does not triple unique coverage. All three outputs are identical; consumed hashes remain unchanged.
- All six external candidate Lua files and the `.lua.txt` harness pass syntax checks.
- Complete production `Charges.lua` and `ExtraButtonSystem/Engine/Button.lua` are loaded. Visibility/grid/glow use unchanged contiguous production function blocks with declared model dependencies. The existing Secrets module and stock sweep queue functions execute as production source. These are explicit model boundaries, not native client launches.
- Guard controls distinguish `issecretvalue=true` even when `canaccessvalue=true`, and inaccessible values when the secrecy flag is false. Neither type checks alone nor one predicate alone are treated as permission.

The four `READINESS_GATE` observations deliberately show that getter-call denial remains unresolved for QuietGrid, core bling, Extra numeric and Extra duration appearance. Their confirmation is **not** a passed native fix. Existing narrow Cast/BadgeHost getter guards can retain their owner-configured zero policy when the getter throws. The library candidate avoids its getter entirely.

Public cooldown controls retain threshold, bling, edge and swipe behavior. The unknown-alpha controls start with known prior appearance, verify that timers continue while that appearance is retained, then expose a public alpha and invoke the normal next paint. Charges recovers on an otherwise unchanged signature without sending `SetCooldown` again; ready/clear still disables bling. These tests do not prove what a first-ever private cooldown should look like or guarantee an immediate Lua paint when access changes. That uncertainty stays open instead of substituting a made-up alpha0 or alpha1.

## QuietGrid work budget

The candidate preserves the public-zero fast path rather than unconditionally writing alpha on every sweep. The harness executes the actual `RunStockSweep`/`RequestStockSweep` production queue against model timers: 1,000 requests in each of 100 frames coalesce into 100 sweep calls. The fixture selects 36 objects (12 stock action buttons,12 button containers and12 allowed bars) and retains stance/possess exclusions. `CanReplaceBar` is explicitly modeled true for this upper-bound selected set; this is not an enumeration of every real client's selected objects.

| Getter state | Reads over100 sweeps | SetAlpha writes | Interpretation |
|---|---:|---:|---|
| Public alpha0, already suppressed | 3,600 | 0 | Same zero-write public idle budget |
| Getter always returns an unreadable value | 3,600 | 3,600 | One explicit suppression reassertion per selected object per coalesced sweep; no1,000-fold setter fan-out |

The private-return case intentionally replaces the former comparison failure with the selected suppression action. It does not introduce an event, timer or recurring driver. A denied getter call remains an application gate. A permitted getter result and permitted `SetAlpha(0)` operation must be verified separately in the relevant native context; the value check does not grant operation permission.

## Glow lifecycle, ownership and cost

The ledger records **21 existing direct alpha-write sites** in initialization and animation callbacks, plus the two recolor-loop writes. It records a value only after the real texture setter succeeds. The six texture keys are spark, innerGlow, innerGlowOver, outerGlow, outerGlowOver and ants. Native animation groups retain their existing child keys, scale/alpha endpoints, order, delays and duration declarations.

Ten cycles retain **80 semantic phase snapshots**, covering appearance play/finish, colored and uncolored reapplication, alpha0 color transitions, stop during appearance, fade-out restart and pool release/reacquisition. Baseline and candidate public states/declarations match. The baseline performs120 texture alpha reads; the candidate performs0. The model creates one glow frame, releases/reuses it20 times and retains **one six-entry ledger table** on that pool-owned frame. It does not allocate a new alpha table each update/recolor. This is a small persistent ownership cost, not a zero-allocation claim. It adds no frame/event/timer driver.

Snapshots compare direct texture base-alpha properties and animation declarations/callback transitions. They do not simulate the native renderer's interpolated output between callbacks, nor prove private-alpha/native animation interaction. Library texture internals are owned by this implementation; other addons directly mutating those private texture properties are not treated as a supported cross-owner write contract. A hot replacement of already-created foreign/untracked library frames is not accepted.

The official upstream was reviewed read-only at [commit4f8f5c2, minor25](https://github.com/Stanzilla/LibCustomGlow/blob/4f8f5c2607d7384b26df9175bb99fa3df891b015/LibCustomGlow-1.0.lua). It still reads/divides `GetAlpha()` in both recolor branches, so a blind upgrade is not an established solution. [Reference metadata](upstream-review.json) pins the commit and file blob. The local proposal changes the frozen embedded minor20 source, preserves its license, and does **not** bump the minor arbitrarily or patch the shared winning library at runtime. If an external minor25 wins LibStub selection, its unmodified implementation remains outside this candidate and ALPHA-06 is not ready to apply as a complete fix. The function-block harness does not test actual LibStub winner selection.
